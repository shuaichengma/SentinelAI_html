# SentinelAI HTML 项目记忆

最后更新：2026-11-16（Asia/Shanghai）

## 用户目标

- 在不改变 SentinelAI 核心功能的前提下，将 Streamlit 交互层转换为传统 HTTP/HTML 应用。
- 新系统独立放在原项目上层目录的 `SentinelAI_html/`，不覆盖原 `SentinelAI/`。
- 登录与上传使用常规 HTML 表单，便于浏览器、Burp Suite 和常规 HTTP 测试工具读取请求。
- 新目录独立维护使用手册、工作记录和记忆文件。

## 当前架构

- Web：Starlette 1.6.0、Jinja2、Uvicorn，服务端渲染 HTML。
- 模型与分析：沿用 Ollama、Qwen3 0.6B、Pydantic Schema、分段合并和三态结论；提示词 1.6.0 明确识别用户名、姓名、部门身份、电话号码、职位、身份证、住址以及无表头 TSV 人员身份组合。评判依据不采用模型复述值，而是按行号从上传文件回填原文，确保不打星号、不脱敏。
- 数据：SQLite 账户、角色、上传归属、报告归属、报告与上传记录关联、IP 封禁和审计日志，`uploads/` 原文件，`data/reports/` 报告。
- 认证：普通用户与管理员入口隔离。`/login` 仅允许普通用户，`/admin_login` 仅允许管理员，入口不在页面中互相链接；管理员 `admin` / `admin@123`、`supuser` / `Supuser@@@123`，普通用户 `user1` / `user1@123`；PBKDF2 哈希、签名 HttpOnly 浏览器会话 Cookie、CSRF Token。登录会话默认空闲 30 分钟失效、最长 8 小时，关闭全部浏览器窗口后 Cookie 不再持久保留。
- 路由：普通用户登录 `/login`，管理员登录 `/admin_login`，分析工作台 `/` 或 `/index`，上传记录 `/history`，管理员文件管理 `/admin`、账户管理 `/admin/accounts`、IP 封禁 `/admin/ip-bans`、日志 `/admin/logs`。
- 端口：HTML 版 8502；原 Streamlit 版 8501，互不覆盖。

## 当前状态

- 独立源码、模板、样式、部署文件和文档已经建立。
- 管理员拥有全部功能，普通用户只能上传、查看自己的文件和执行分析；后台路由对普通用户返回 HTTP 403。
- 登录入口按账户角色强制隔离：认证成功后再校验角色，不建立错误角色的会话。登录页仅展示品牌、账号、密码和登录按钮；跨入口、停用、不存在账户及密码错误对客户端统一返回 HTTP 401 和“账号或密码错误”，不暴露角色、账户状态或正确入口，真实拒绝原因只写入服务端审计日志。未登录访问后台路由跳转 `/admin_login`，未登录访问用户路由跳转 `/login`；管理员退出后回到 `/admin_login`，普通用户退出后回到 `/login`。
- 不存在或停用账户同样执行一次 PBKDF2 占位校验，使失败登录的计算路径保持一致，降低通过响应时间判断账户存在或启停状态的风险。
- 管理后台已有文件管理、账户管理、IP 封禁、系统日志四个左侧导航模块；支持按角色新建账户、删除、启停和改密。`admin` 账户不可删除，但可由其他管理员停用；当前登录账户不能停用自身，系统至少保留一个启用账户。
- 管理后台新增恶意 IP 封禁：支持 IPv4/IPv6、按分钟/小时/天配置 1 分钟至 365 天封禁、填写原因、自动到期、手动解封和记录列表；已过期或已解除的历史记录可通过弹窗重新填写时长和原因后再次封禁。禁止从后台封禁当前管理员请求来源 IP，封禁按服务端直连客户端 IP 生效，不信任 `X-Forwarded-For` 等可伪造头。
- 有效 IP 封禁在请求进入业务路由前由中间件返回 HTTP 403，并写入“IP 封禁 / IP 封禁拦截”审计；管理员封禁和解除操作也写入审计。
- 正式数据库新增 IP 封禁表前已停服备份为 `data/sentinelai.db.before-ip-ban-20261116`；真实 HTTP 已验证临时封禁来源返回 403、手动解封后恢复 200，服务保持 active。
- 上传记录和报告带所有者信息，普通用户不能通过上传 ID 或报告路径访问其他用户内容；旧版未归属文件仅管理员可访问。
- `/history` 为上传历史入口：普通用户只看到自己的文件，管理员看到全部用户记录。每个文件显示待分析/已分析状态、最近分析时间和最近 JSON/Markdown 报告入口，可重新打开上传文件分析。
- 分析报告表新增 `upload_id` 关联和索引，分析完成后保存报告任务与源上传记录的映射；旧报告保留原有所有者信息，未关联记录不会猜测绑定。
- AI 分析表单提交后会锁定按钮并显示不确定进度动画，避免等待期间重复提交。
- SQLite 审计日志记录登录/注销、账户变更、文件操作及 HTTP 网络流量，并标记失败登录和异常路径探测样本。成功下载 JSON/Markdown 分析报告会记录“文件操作 / 下载分析报告”，包含报告编号、格式、下载账户和角色；日志页面支持分页、每页 10～500 条、总数显示、单条删除、全部删除及当前类别筛选结果的 CSV 导出。CSV 使用 UTF-8 BOM 并防护表格公式注入，导出行为本身也会审计。
- 真实 HTTP 已验证历史 IP 再次封禁弹窗和按“IP 封禁”类别导出 CSV，CSV 下载与对应导出审计均正常，服务保持 active。
- 分析页双栏采用固定等宽和独立内容滚动，文件内容不再撑大组件；数据库继续以 UTC 保存时间，所有页面、CSV 导出、封禁提示和 Markdown 报告时间统一转换为中国时间（UTC+8），后台时间采用易读、禁止折行的统一格式，账户操作保持单行且停用按钮使用橙色。
- 停用账户登录时，无论密码是否正确，均与跨入口、密码错误和账户不存在使用相同的 HTTP 401 通用失败响应；停用登录拒绝会写入审计日志。
- 自动化测试共 68 项，覆盖中国时间（UTC+8）转换及报告时区、双登录入口隔离、角色不匹配拒绝、浏览器会话 Cookie、空闲及最长登录时限、IP 封禁生命周期、历史再次封禁与中间件拦截、日志筛选导出、角色权限、上传历史隔离、管理员全量视图、上传/报告归属与关联、普通用户报告下载审计、`user1` 初始化、`admin` 删除保护和旧库升级。
- 正式数据库已在停服状态下备份为 `data/sentinelai.db.before-history-migration-20261109`，完成报告 `upload_id` 幂等迁移并重启服务；原有 12 条上传记录保持完整。
- 真实 HTTP 验证普通用户仅看到自己的新上传记录、管理员看到该记录及上传用户；验证文件随后由管理员清理，服务保持 active。
